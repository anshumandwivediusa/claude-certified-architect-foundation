# 02. The Agentic Loop Lifecycle

## Lifecycle Phases
1. **Request**  
   - User provides input or task specification.  
   - Starting point of the loop.  

2. **Model Reasoning**  
   - Model interprets intent and plans next step.  
   - Decides whether knowledge suffices or a tool is needed.  

3. **Tool Selection**  
   - Chooses the most appropriate tool(s) based on schema and availability.  
   - Critical exam point: selection must match task type (e.g., search vs. calculator).  

4. **Tool Execution**  
   - External system runs with given parameters.  
   - Produces authoritative results.  

5. **Tool Result**  
   - Output injected back into conversation state as `tool_result`.  
   - Ensures continuity and prevents hallucination.  

6. **Next Model Turn**  
   - Model consumes tool results.  
   - Decides continuation (loop again) or termination.  
```
import anthropic

client = anthropic.Anthropic()

# -------------------------------
# Define banking tool
# -------------------------------
tools = [
    {
        "name": "validate_customer",   # Tool name
        "description": "Validate customer account and KYC status",  # Purpose
        "input_schema": {              # Schema defines required inputs
            "type": "object",
            "properties": {
                "customer_id": {"type": "string"},
                "account_number": {"type": "string"}
            },
            "required": ["customer_id", "account_number"],  # Both must be provided
        },
    }
]

# -------------------------------
# Tool execution logic
# -------------------------------
def execute_tool(name, tool_input):
    if name == "validate_customer":
        # Simulated validation logic
        if tool_input["customer_id"] == "CUST123" and tool_input["account_number"] == "ACC456":
            return "Customer is valid: KYC complete, account active, no fraud flags."
        else:
            return "Customer validation failed: account inactive or KYC pending."
    return "unknown tool"  # Fallback if tool name not recognized

# -------------------------------
# Initial user request
# -------------------------------
messages = [{"role": "user", "content": "Validate customer CUST123 with account ACC456"}]

# -------------------------------
# Agentic execution loop
# -------------------------------
while True:
    response = client.messages.create(
        model="claude-sonnet-5",   # Model used for reasoning
        max_tokens=1024,           # Token budget
        tools=tools,               # Available tools
        messages=messages,         # Conversation history
    )

    # Append model response to conversation
    messages.append({"role": "assistant", "content": response.content})

    # -------------------------------
    # Interpret stop_reason
    # -------------------------------
    match response.stop_reason:

        case "tool_use":
            # Model requested tool execution → continue loop
            tool_results = []
            for block in response.content:
                if block.type == "tool_use":
                    # Execute tool with given input
                    result = execute_tool(block.name, block.input)
                    # Return tool result back into conversation
                    tool_results.append({
                        "type": "tool_result",
                        "tool_use_id": block.id,
                        "content": result,
                    })
            # Inject tool results for next model turn
            messages.append({"role": "user", "content": tool_results})
            continue  # Loop continues

        case "pause_turn":
            # Model paused → wait for next iteration
            continue

        case "end_turn" | "stop_sequence":
            # Model considers task complete → terminate loop
            final_text = "".join(b.text for b in response.content if b.type == "text")
            print(final_text)
            break

        case "max_tokens":
            # Token budget exceeded → truncate or retry
            print("Truncated — consider raising max_tokens or summarizing history.")
            break

        case "refusal":
            # Model refused task → reset or exit
            print("Refused:", response.stop_reason, getattr(response, "stop_details", None))
            messages = messages[:1]  # Reset to initial request
            break

        case "model_context_window_exceeded":
            # Context too large → trim history and retry
            print("Hit context window — trim or summarize `messages` and retry.")
            break
```

##### Tool vs Knowledge in Agentic AI

- **LLM knowledge** → Claude can directly answer general questions (e.g., “KYC = Know Your Customer, a regulatory identity verification process”).  
- **Tool invocation** → If a tool is defined (`whatIsKYC`), Claude may prefer calling it for **authoritative, structured, or policy-grounded answers**.  
- **Decision logic** →  
  - If the query is **generic** → respond directly with text.  
  - If the query matches a **tool schema** → emit `tool_use`.  
  - If both apply → Claude often **calls the tool first**, then enriches with its own knowledge.  
- **stop_reason** →  
  - `"end_turn"` → answered directly from knowledge.  
  - `"tool_use"` → invoked the tool.  
  - Hybrid → `"tool_use"` followed by `"end_turn"` after tool_result.  
- **Best practice** → Use tools for **specific, dynamic, or compliance-critical tasks**, and let LLM knowledge provide **contextual explanation**.

### Key Takeaways

- **Sequential Lifecycle**  
  Request → Reasoning → Selection → Execution → Result → Next Turn.  
  **Key Concept:** Always linear, no skipping phases.  
  **Exam Trap:** Writing “execution before reasoning” or omitting *tool result injection*.  

- **Stop Reasons** control loop flow:  
  - `tool_use` → Continue loop with tool execution.  
  - `end_turn` → Task complete, terminate safely.  
  - `pause_turn`, `refusal`, `max_tokens` → Special handling.  
  **Key Concept:** Stop reasons are **signals**, not errors.  
  **Exam Trap:** Confusing `tool_use` with “loop termination.”  

- **Tool Results Injection**  
  Must be returned into conversation as `tool_result`.  
  **Key Concept:** Ensures continuity of reasoning.  
  **Exam Trap:** Forgetting to inject results → model hallucinates state.  

- **Loop Control Mechanisms**  
  - Timeouts → Prevent resource drain.  
  - Iteration budgets → Cap maximum turns.  
  - Error thresholds → Abort after repeated failures.  
  **Key Concept:** Safety nets against runaway loops.  
  **Exam Trap:** Assuming “infinite retries” are allowed — they are not.  

- **Termination Criteria**  
  Explicit exit conditions:  
  - Task complete (natural end).  
  - Stop signal (user/system directive).  
  - Escalation (handoff to agent/human).  
  **Key Concept:** Every workflow must define an exit.  
  **Exam Trap:** Leaving termination implicit → risk of infinite loop.  


## ⚠️ Common Exam Traps
- Mixing up **reasoning vs. execution** order.  
- Forgetting **tool_result injection** step.  
- Treating `tool_use` as termination instead of continuation.  
- Assuming loops run indefinitely without **budgets/timeouts**.  
- Not stating **explicit termination criteria** in workflow design.  



## Interpreting `stop_reason`
- **tool_use** → Execute requested tool, continue loop.  
- **end_turn** → Model considers task complete, loop terminates.  
- **pause_turn** → Loop cap reached, architect must resend without new input.



## Returning Tool Results
- Results must be **injected** back into the conversation as `tool_result`.  
- Ensures continuity of reasoning and avoids hallucinated state.  
- Each result is treated as authoritative input for the next model turn.



## Loop-Control Mechanisms
- **Task-complete termination** → Natural end when output satisfies request.  
- **Explicit stop signals** → User or system directive halts loop.  
- **Error/failure thresholds** → Abort after repeated tool errors.  
- **Maximum turns / iteration budgets** → Safety cap on loop length.  
- **Timeout/resource limits** → Prevents runaway resource consumption.  
- **Escalation** → Hand off to another agent or human if unresolved.



## Runaway-Loop Prevention
- **Avoid infinite tool calls** → Detect repeated identical calls.  
- **Limit retries** → Cap on failed attempts.  
- **Define clear termination criteria** → Ensure every workflow has an exit condition.
